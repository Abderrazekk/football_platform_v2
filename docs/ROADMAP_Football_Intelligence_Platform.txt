GOLDEN RULES (read them again at the start of every week)
---------------------------------------------------------
1. A small finished project beats a huge unfinished one. MVP first.
2. Never train a model inside Django. Train in ml/, save .joblib, load in Django.
3. No data leakage: a match feature may only use data from BEFORE that match.
4. Always split by time (train 2020-24 / validation 2024-25 / test 2025-26),
   never randomly. The test set is used ONCE, at the very end.
5. Always compare to baselines. A model without a baseline means nothing.
6. Commit to Git at least once per working day, with a clear message.
7. Be honest about accuracy: 50-55% on 1/X/2 is already a good result.
8. Notebooks for experiments, .py scripts for final code.
9. SIMPLE CODE: if you cannot explain a line in 10 seconds, rewrite it.
10. One ML step = one file. Each file reads one input and writes one output.

CODING RULES (student-simple code)  -> applies to ML and Django
---------------------------------------------------------------
DO
  - Short functions (about 20 lines max), one job per function.
  - Clear names: train_matches, home_elo, load_clean_matches().
  - Classic for loops and if statements, step by step.
  - A header comment at the top of EVERY script:
        # FILE   : 03_preprocessing.py
        # ROLE   : clean the raw matches (names, dates, missing values)
        # INPUT  : data/processed/all_matches_raw.csv
        # OUTPUT : data/processed/clean_matches.csv
        # RUN    : python ml/match_model/03_preprocessing.py
  - Put paths, SEED = 42, season lists and column lists in ml/config.py.
  - Put small shared helpers in ml/utils.py (load_csv, save_json, metrics).
  - Print simple messages while running ("Loaded 2660 matches").
  - Django: function-based views, logic in services.py, thin views.
AVOID
  - Metaclasses, custom decorators, nested comprehensions, lambda chains,
    multiple inheritance, clever one-liners, over-engineering.
  - Extra libraries: stay with pandas, numpy, scikit-learn, xgboost, joblib,
    matplotlib, pulp.
TIP (how scripts find ml/config.py when run from the project root)
  Put these lines at the top of each script, then write "import config":
        import sys
        from pathlib import Path
        sys.path.append(str(Path(__file__).resolve().parent.parent))

PHASE 3 - FEATURE ENGINEERING FOR THE MATCH MODEL   (Week 3)   ML step 04
==============================================================================
GOAL: a leak-free feature table, one row per match, ready for training.
Files: ml/match_model/04_feature_engineering.py + notebooks/02_match_model.ipynb
       (notebook = tests of ideas only; the final code is the .py script)

CONCEPT: process matches in chronological order. For each match, compute
features using ONLY matches with date < current match date. Write it with
simple loops (one pass through the matches, dictionaries to store team state).

TASKS
[ ] [M] Target variable: FTR in {H, D, A} (encode 0/1/2 using config.py).
[ ] [M] Elo rating per team:
          expected_home = 1 / (1 + 10 ** ((elo_away - (elo_home + HOME_ADV)) / 400))
          update: elo += K * (actual - expected)   (K ~ 20, HOME_ADV ~ 60-100)
          Start every team at 1500; for promoted teams use a lower start value
          or the average of relegated teams. Store elo_home, elo_away, elo_diff
          BEFORE the update.
[ ] [M] Rolling form features (last 5 and last 10 matches, per team, shifted so
        the current match is excluded): points per game, goals for, goals
        against, goal difference, win rate.
[ ] [M] Home form (last 5 home matches) and away form (last 5 away matches).
[ ] [M] Rest days since previous match.
[ ] [M] Head-to-head features: over the last N meetings (use all 7 seasons):
        home wins, draws, away wins, average goal difference.
[ ] [S] Advanced stats (Understat): rolling xG for / xG against (last 5).
        Handle seasons without Understat.
[ ] [S] Squad-quality features from player data: average rolling points of the
        team's top players before the match, minutes continuity, injuries
        proxy (players with 0 minutes recently).
[ ] [S] Season context: gameweek number, early-season flag (few matches played).
[ ] [C] Bookmaker implied probabilities (normalized 1/odds). Keep them in a
        SEPARATE feature set: main model WITHOUT odds, benchmark WITH odds.
[ ] [M] Cold start rule: first matches of a season/team have little history ->
        use priors (league average / Elo start) and add a "matches_played"
        feature, or drop the first 3-5 gameweeks of 2020-21 from training.
[ ] [M] Save: data/processed/features.csv (one row per match, including
        upcoming 2026-27 fixtures with an empty target), the ordered feature
        list ml/artifacts/features_list.json, and data/processed/
        team_latest_state.csv (latest Elo, form, rest days per team, used by
        predict.py to build features for any future match).
[ ] [M] LEAKAGE TEST (tests/test_no_leakage.py): for random matches, recompute
        features using only earlier matches and assert equality; assert no
        column comes from the match itself (goals, shots, xG of that match).

DELIVERABLES: 04 script, features.csv, features_list.json, leakage test.
DONE WHEN: the table has no NaN issue you did not decide on, and the leakage
test passes.
