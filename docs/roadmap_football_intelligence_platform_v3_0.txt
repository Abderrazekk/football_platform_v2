WHAT CHANGED COMPARED TO ROADMAP v2.0
------------------------------------
1. 100% JUPYTER NOTEBOOKS (.ipynb) FOR ML: Zero .py files in ml/ (no config.py,
   no utils.py, no predict.py, no separate notebooks/ folder). Every ML step is
   a self-contained .ipynb notebook executed top-to-bottom via
   "Kernel -> Restart & Run All" (just like in your class TPs).
2. DIRECT DJANGO BRIDGE (services.py): Django apps (matches/services.py,
   players/services.py, season/services.py) load the exported .joblib models,
   StandardScalers, and .json feature lists once at startup via joblib.load().
3. STRICT RECYCLING OF THE 4 ML COURSE CHAPTERS:
   - Chapter 1: Supervised vs. Unsupervised paradigms, chronological split,
     zero data leakage, StandardScaler fitted strictly on the train set.
   - Chapter 2: Multiple Linear Regression, Ridge (L2), Lasso (L1) evaluated
     with MAE, RMSE, MSE, and R2.
   - Chapter 3: Multinomial Logistic Regression (Softmax), Decision Tree
     (Gini/Entropy), Bagging (Random Forest), Boosting (Gradient Boosting &
     XGBoost), and Stacking (top 2 models + Logistic Regression meta-model)
     evaluated with Confusion Matrix, Accuracy, Precision, Recall, F1-Score,
     and Log Loss.
   - Chapter 4: Unsupervised Clustering with K-Means (K chosen via Elbow
     Method and Silhouette Coefficient) compared with DBSCAN / Hierarchical
     Clustering to segment team and player playing styles.
4. REMOVED OUT-OF-SCOPE ITEMS: Dropped PuLP, Brier score, Platt/isotonic
   calibration, Spearman correlation, Poisson goals model, Monte-Carlo table
   simulation, and optional walk-forward script 11. Best XI uses a simple
   greedy algorithm under squad constraints.

GOLDEN RULES (read them again at the start of every week)
---------------------------------------------------------
1. A small finished project beats a huge unfinished one. MVP first.
2. Never train a model inside Django. Train in ml/*.ipynb, save .joblib, load
   in apps/<app>/services.py.
3. No data leakage: a match/gameweek feature may only use data from BEFORE
   that match. Fit StandardScaler ONLY on train.csv.
4. Always split by time (train 2020-24 / validation 2024-25 / test 2025-26),
   never randomly. The test set is used ONCE, at the very end.
5. Always compare to baselines. A model without a baseline means nothing.
6. Commit to Git at least once per working day, with a clear message.
7. Be honest about accuracy: 50-55% on H/D/A is already a good result.
8. 100% .ipynb in ml/: every notebook must run cleanly from Cell 1 to the last
   cell using "Kernel -> Restart & Run All" without errors.
9. SIMPLE CODE: if you cannot explain a line in 10 seconds, rewrite it.
10. One ML step = one .ipynb notebook reading one input and writing one output.

CODING RULES (student-simple code)  -> applies to ML notebooks & Django
-----------------------------------------------------------------------
DO
  - Short functions (about 20 lines max), one job per function.
  - Clear names: train_matches, home_form_pts, load_clean_matches().
  - Classic for loops and if statements, step by step.
  - A Markdown cell at the top of EVERY .ipynb notebook explaining:
        # NOTEBOOK : 03_preprocessing.ipynb
        # ROLE     : Clean raw matches (team names, dates, missing values)
        # INPUT    : ../../data/processed/all_matches_raw.csv
        # OUTPUT   : ../../data/processed/clean_matches.csv
  - Define paths, RANDOM_STATE = 42, season lists, and column lists in Cell 1
    of each notebook.
  - Print clear progress messages ("Loaded 2660 matches").
  - Django: function-based views, logic and joblib.load() in services.py,
    thin views.
AVOID
  - Metaclasses, custom decorators, nested comprehensions, lambda chains,
    multiple inheritance, clever one-liners, over-engineering.
  - Extra libraries: stay strictly with pandas, NumPy, scikit-learn, XGBoost,
    joblib, matplotlib.
